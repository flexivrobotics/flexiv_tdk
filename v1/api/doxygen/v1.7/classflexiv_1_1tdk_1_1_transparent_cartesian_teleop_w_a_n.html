Detailed Description

  • Standard Edition ([NetworkCfgStd]): the two sides connect directly to each other via TCP. One side needs a public IP address and port forwarding.
  • Professional Edition ([NetworkCfgPro]): both sides connect to TDK Server, which routes messages between them. Messages are encrypted and authenticated. No public IP address or port forwarding is required; each side only needs Internet access.
    Note
    In the documentation of this class, "WAN connection" refers to the communication link between the two sides of teleoperation, and "message latency" refers to the end-to-end latency of messages received from the other side over this link.
    Warning
    This is highly transparent Cartesian teleoperation and therefore requires the robot to be configured with a flange-end FT sensor before using this class.
    Note
    In the documentation of this class, "leader robot" refers to the robot which operated by a human operator during teleoperation; "follower robot" refers to the robot interacts with workpieces.

◆ CheckTeleopConnectionLatency()

bool flexiv::tdk::TransparentCartesianTeleopWAN::CheckTeleopConnectionLatency ( unsigned int idx,
double & latency_ms ) const

Estimates the average message latency (in milliseconds) using an internal sliding-window filter to suppress transient spikes. The computed value is returned via [latency_ms].

Interpretation of return value and latency:

  • Not connected: No message has been received from the peer yet, or none for more than 1 s. [latency_ms] is a very large positive value. Returns false.
  • Connected: [latency_ms] ∈ [0, threshold_ms]. Returns true. The default threshold is 200 ms and can be modified via SetTeleopLatencyLimit().
  • Over limit: Messages arrive later than threshold_ms, or none has arrived for more than threshold_ms (in which case [latency_ms] is at least the time since the last message). Returns false.
  • Clock mismatch: [latency_ms] is negative. Returns false. Ensure both computers synchronize system time (e.g., using chrony).
Parameters
[in]idxIndex of the robot pair corresponding to [robot_pairs_sn].
[out]latency_msEstimated average message latency in milliseconds.
Returns
True if the connection is established and latency is within [0, threshold_ms]; otherwise false.
Exceptions
std::invalid_argumentIf [idx] is out of range.
Warning
  • Latency > 200 ms indicates poor connection quality and may cause delayed feedback or command execution.
  • If latency exceeds threshold_ms, or is negative (clock mismatch), teleoperation is disengaged and follower robots hold their pose until latency returns to a valid range.
See also
SetTeleopLatencyLimit()

Note
This function blocks until the request is successfully delivered.
Null-space posture control
Similar to human arm, a robotic arm with redundant joint-space degree(s) of freedom (DoF > 6) can change its overall posture without affecting the ongoing primary task. This is achieved through a technique called "null-space control". After the reference joint positions of a desired robot posture are set using this function, the robot's null-space control module will try to pull the arm as close to this posture as possible without affecting the primary Cartesian motion-force control task.
